通常来说，你会通过 props 将信息从父组件传递到子组件。但是，如果你必须通过许多中间组件向下传递 props，或是在你应用中的许多组件需要相同的信息，传递 props 会变的十分冗长和不便。**Context** 允许父组件向其下层无论多深的任何组件提供信息，而无需通过 props 显式传递。

## 传递 props 带来的问题

传递 props 是将数据通过 UI 树显式传递到使用它的组件的好方法。

但是当你需要在组件树中深层传递参数以及需要在组件间复用相同的参数时，传递 props 就会变得很麻烦。最近的共同祖先组件可能离需要数据的组件很远，状态提升 到太高的层级会导致 “逐层传递 props” 的情况。

## Context：传递 props 的另一种方法

Context 让父组件可以为它下面的整个组件树提供数据。



### 1.创建 context

首先，你需要创建这个 context，并 **将其从一个文件中导出**，这样你的组件才可以使用它：

```js title="LevelContext.js"
import { createContext, useContext } from 'react';

// 1. 创建 Context
const ThemeContext = createContext(null);
```

`createContext` 只需**默认值**这么一个参数。这个参数可以是任意类型



### 2.上层组件提供数据

```jsx
// 2. 上层组件提供数据
function App() {
  const [theme, setTheme] = useState('dark');

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Page />
    </ThemeContext.Provider>
  );
}
```



<Callout title="注意" type="warning">

React 19 起可省略 .Provider，你可以直接：

```jsx
    <Provider value={{ theme, setTheme }}>
      <Page />
    </Provider>
```

</Callout>



### 3.任意深度的后代消费

```jsx
// 3. 任意深度的后代消费
function Button() {
  const { theme, setTheme } = useContext(ThemeContext);
  return (
    <button className={theme} onClick={() => setTheme('light')}>
      切换主题
    </button>
  );
}
```

useContext查找规则：

1. 沿渲染树向上找最近的 `<ThemeContext.Provider>`，返回它的 `value`
2. 一路都没有 → 返回 `createContext(defaultValue)` 里的默认值

找到后它不只是“读一次”，而是订阅：Provider 的 `value` 变化时，所有消费组件自动重渲染。



## Context的更新

Context 的更新不走“父→子”的普通重渲染链路。当某个 Provider 的 `value` 变化时，React 做的不是“重渲染这个 Provider 的所有后代”，而是：

> 直接遍历 fiber 树 → 找出所有**订阅了这个 context**的组件 → 只让它们重渲染

中间那些没调用 `useContext(ThemeContext)` 的组件（哪怕就夹在 Provider 正下方）完全不参与。这是 context 特有的“精准推送”。

## 结合使用 reducer 和 context

```js tab="TasksContext.js"
// TasksContext.js
import { createContext, useContext, useReducer } from 'react';

const TasksContext = createContext(null);
const TasksDispatchContext = createContext(null);

export function TasksProvider({ children }) {
  const [tasks, dispatch] = useReducer(tasksReducer, initialTasks);

  return (
    <TasksContext.Provider value={tasks}>
      <TasksDispatchContext.Provider value={dispatch}>
        {children}
      </TasksDispatchContext.Provider>
    </TasksContext.Provider>
  );
}

export function useTasks() {
  return useContext(TasksContext);
}

export function useTasksDispatch() {
  return useContext(TasksDispatchContext);
}

function tasksReducer(tasks, action) {
  switch (action.type) {
    case 'added': {
      return [...tasks, {
        id: action.id,
        text: action.text,
        done: false
      }];
    }
    case 'changed': {
      return tasks.map(t => {
        if (t.id === action.task.id) {
          return action.task;
        } else {
          return t;
        }
      });
    }
    case 'deleted': {
      return tasks.filter(t => t.id !== action.id);
    }
    default: {
      throw Error('未知 action: ' + action.type);
    }
  }
}
```

```jsx tab="App.js"
<TasksProvider>
  <h1>待办清单</h1>
  <AddTask />
  <TaskList />

```



为什么拆成两个 Context？

`tasks` 频繁变化，但 `dispatch` 引用永远稳定

```jsx
<TasksContext.Provider value={tasks}>              ← 这个会变
<TasksDispatchContext.Provider value={dispatch}>   ← 这个【永远不变】
```



```
tasks 变化
→ TasksContext 的 value 变了
   ├─ TaskList  ✅ 重渲染
   └─ 统计栏    ✅ 重渲染
→ TasksDispatchContext 的 value 还是原来那个函数，引用没变
   └─ AddTask   💤 React 直接跳过，不渲染
```

完整时序

```
点击"添加"
→ tasksReducer 返回新数组，tasks 变化
→ TasksProvider 函数重新执行
→ React 对比返回的 JSX：
    TasksDispatchContext.Provider：value 还是那个 dispatch → 跳过其子树
    children：还是 App 给的那批旧元素 → 跳过
→ 但 TasksContext 的 value 变了
→ React 单独通知订阅者：TaskList ✅、统计栏 ✅
→ AddTask 只订阅 DispatchContext，且该 context 没变 💤
```
