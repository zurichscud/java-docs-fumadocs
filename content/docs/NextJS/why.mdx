## SSR

客户端渲染

浏览器拿到几乎空的 HTML（只有一个 `<div id="root">` 和一个 `<script>`），下载并执行 JS 后才由 JS 生成整棵 DOM。缺点是首屏白屏时间长、SEO 差。

## CSR

服务端渲染

服务器把组件渲染成完整 HTML 字符串返回，浏览器立刻就能显示。首屏快、SEO 好。

## Hydration（水合）

SSR 产出的是“死” HTML

- 脱水

服务端渲染出来的只是一段静态标记：没有事件监听、没有组件状态、没有交互逻辑。按钮看起来能点，点了没反应。这个阶段叫“脱水”状态。

```js
// server.js —— 运行在 Node
app.get('/', (req, res) => {
  const html = renderToString(<App />);
  res.send(`
    <body>
      <div id="root">${html}</div>
      <!-- 客户端 JS 在这里被"种"进页面 -->
      <script src="/assets/client.js"></script>
    </body>
  `);
});
```

- 水合

让 HTML 复活的过程，就是水合：干瘪的 HTML 加上客户端 JS 这瓶“水”，就活了。

```js
// client.js —— 打包产物，浏览器下载后执行
import { hydrateRoot } from 'react-dom/client';
import App from './App';

hydrateRoot(document.getElementById('root'), <App />);
```



完整流程：

1. 构建时：打包器产出服务端 bundle + 客户端 bundle（多个 chunk）
2. 请求时：Node 执行服务端 bundle → 生成 HTML + `<script>` 标签 → 返回浏览器
3. 浏览器解析 HTML：立即显示内容（FCP），同时并行下载 JS
4. JS 下载执行：同一个 `App` 组件在浏览器重新跑一遍，对上现有 DOM → 水合完成（TTI）
