`ReadableStream` 是 Web API（Streams API）中用于处理可读数据流的核心接口。

你可以自由设计数据读取的两端。

## 核心部件

- **Underlying Source（底层源）**：数据的真正来源（如网络 Socket、文件系统、本地生成的算法数据）。

- **Controller（控制器）**：用于向流中压入数据（`enqueue`）、抛出错误（`error`）或关闭流（`close`）。

- **Reader（读取器）**：流的唯一访问入口。一旦流被锁定（locked）给某个 Reader，其他代码就无法同时读取。

## 创建ReadableStream

你可以通过构造函数传入 `start`、`pull`、`cancel` 等钩子函数来自定义一个读取流：

```js
const customStream = new ReadableStream({
  start(controller) {
    // 流初始化时触发，可以压入初始数据
    controller.enqueue("Hello");
    controller.enqueue(" World!");
    controller.close(); // 标记数据发送完毕
  },
  pull(controller) {
    // 当内部缓冲区未满且 Reader 请求更多数据时触发
  },
  cancel(reason) {
    // 当 Reader 显式取消流时触发
  },
});
```

## 读取数据

### 出口

使用 `getReader()` 锁住流，并通过 `read()` 循环获取数据块：

```js
const reader = customStream.getReader();

async function readStream() {
  while (true) {
    // read() 返回 { value: Chunk, done: boolean }
    const { value, done } = await reader.read();

    if (done) {
      console.log("流已完全读取完毕");
      break;
    }

    console.log("读取到的数据块:", value);
  }
}

readStream();
```

<Accordions type="single">
  <Accordion title="为什么需要 Reader？">
    在 Streams API 中，流是可共享的资源。为了确保数据的一致性和避免竞争条件，流在被读取时会被锁定给一个 Reader。这样可以保证同一时间只有一个读取器在处理流的数据，避免了多线程/多任务环境下的数据冲突问题。

Java 当时为什么不这样设计：1996 年采用的是“同步阻塞 + 显式 Buffer 传参”范式，简单直观，在当时的单线程/多线程模型下完全够用。

## 使用 `for await...of` 简化读取

在较新的浏览器和 Node.js 环境中，`ReadableStream` 实现了**异步迭代**协议，读取变得非常优雅：

```js
for await (const chunk of stream) {
  console.log("Chunk:", chunk);
}
```

> 没有必要关心每次chunk读取的内容，你只需要知道连在一起就是完整的内容

## 背压控制

当数据生产的速度**快于**读取消费的速度时，`ReadableStream` 提供了背压机制，通过内部队列与 `pull()` 的配合，自动限制生产端的节奏：

```js
let i = 0;

// 1. 创建可读流（内部队列最多缓存 2 个数据块）
const readableStream = new ReadableStream(
  {
    // 每次 pull 生产一个数据块
    pull(controller) {
      const chunk = `Chunk-${++i}`;
      console.log(`⚡ [生产者] 生产数据: ${chunk}`);
      controller.enqueue(chunk);
    },
  },
  new CountQueuingStrategy({ highWaterMark: 2 }),
);

// 2. 获取锁定读取器
const reader = readableStream.getReader();

// 3. 模拟慢速消费，利用背压限制生产节奏
async function consume() {
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    console.log(`🐢 [消费者] 读取数据: ${value}`);
    await new Promise((r) => setTimeout(r, 1000)); // 模拟耗时消费操作（1000ms）
  }
}

consume();
```

- `highWaterMark:2`：缓冲区大小为 **2 个数据块**

- **`controller.desiredSize`**：表示队列剩余可写入空间，当其小于等于 `0` 时，说明可读流内部队列已满。

- **`pull()` 只在队列未满时被调用**：背压的核心。队列满时流会**自动停止调用 `pull()`**，生产随之暂停（此时控制台只会看到先产出的 2 个 Chunk）；等到消费者 `read()` 取走数据、队列腾出空间后，流才会再次调用 `pull()` 生产下一块数据。

## Example

处理 Fetch 流式响应

```js
async function fetchStreamText() {
  const response = await fetch("https://api.example.com/stream");

  // response.body 即是一个 ReadableStream<Uint8Array>
  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8"); // 用于将 Uint8Array 转为字符串

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    // 解码并实时打印/渲染到界面上
    const textChunk = decoder.decode(value, { stream: true });
    console.log("收到新片段:", textChunk);
  }
}
```
