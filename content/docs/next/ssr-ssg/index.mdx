## CSR

客户端渲染（Client Side Rendering）

浏览器拿到几乎空的 HTML（只有一个 `<div id="root">` 和一个 `<script>`），下载并执行 JS 后才由 JS 生成整棵 DOM。缺点是首屏白屏时间长、SEO 差。

常见场景：

- 后台管理系统开发(后台系统不需要SEO，也不需要首屏加载速度)
- 单页面应用开发(SPA)

## SSR

服务端渲染（Server Side Rendering）

服务器把组件渲染成完整 HTML 字符串返回，浏览器立刻就能显示。首屏快、SEO 好。

常见场景：

- 电商网站开发
- 博客网站开发
- 官网/首页等

## SSG

静态站点生成（Static Site Generation）

例如我们需要一个查看文档的网站，例如`Vue` `React` 等文档，大家看到的都是一样的，所以我们在构建的时候，直接编译成静态文件，连接口都不用请求了，如果在部署CDN/Nginx等服务器，基本可以实现秒开。



## ISR

增量静态生成

- **核心机制**：结合了 SSG 的速度与 SSR 的灵活性。支持在构建完成后，按设定的时间间隔（如 `revalidate: 60`）在后台异步重新生成静态页面。

- **适用场景**：数据量庞大且内容有更新需求的页面（如：电商商品详情页、新闻列表页）。

- **优缺点**：兼具极致访问速度与数据渐进更新能力，大幅减轻服务器实时渲染负担。

## Hydration（水合）

- 脱水

服务端渲染出来的只是一段静态标记：没有事件监听、没有组件状态、没有交互逻辑。按钮看起来能点，点了没反应。这个阶段叫“脱水”状态。

```js
// server.js —— 运行在 Node
app.get('/', (req, res) => {
  const html = renderToString(<App />);
  res.send(`
    <body>
      <div id="root">${html}</div>
      <!-- 客户端 JS 在这里被"种"进页面 -->
      <script src="/assets/client.js"></script>
    </body>
  `);
});
```

- 水合

让 HTML 复活的过程，就是水合：干瘪的 HTML 加上客户端 JS 这瓶“水”，就活了。

```js
// client.js —— 打包产物，浏览器下载后执行
import { hydrateRoot } from 'react-dom/client';
import App from './App';

hydrateRoot(document.getElementById('root'), <App />);
```

水合是 React 将事件处理器附加到 DOM 上，使静态 HTML 变得可交互的过程。
