## 静态路由

如果是**没有路径参数**的普通页面（如 `app/about/page.tsx`）：自动优化为纯静态 (SSG)

```tsx
// app/about/page.tsx
export default function About() {
  return <div>HelloWorld</div>
}
```

Next.js **不需要**你写任何配置，会在构建时自动发现这个页面完全不依赖任何请求头（Headers）、Cookie 或服务端动态数据，直接把它优化为纯静态的 `about.html` 。

## 动态路由

如果你的页面是一个**动态路由**（如 `app/posts/[id]/page.tsx`）：

```tsx title="app/posts/[id]/page.tsx"
// app/posts/[id]/page.tsx
export default function Post() {
  return <div>HelloWorld</div>
}
```

Next.js 不会自动把 `/posts/1`、`/posts/2` 预先优化成静态 HTML。因为在打包的时刻，Next.js **根本不知道 `[id]` 可能代表什么**：

- 它不知道你的数据库里有哪些文章 ID。

- 它不知道用户可能会输入 `/posts/1` 还是 `/posts/abc`。

所以，即使你的组件内部简单到只有 `HelloWorld`，只要它带了 `[id]` 这个动态占位符，打包系统就会把这个路由标记为 **ƒ (Dynamic)**。

## 动态路由静态化

你必须通过 `generateStaticParams` 显式告诉打包器：“**虽然这是动态路由，但 `id` 为 1、2、3 的这几个页面，请帮我按照静态 HTML 提前打包出来。**”

```tsx title="app/posts/[id]/page.tsx"
// app/posts/[id]/page.tsx
export async function generateStaticParams() {
  return [{ id: '1' }, { id: '2' }, { id: '3' }];
}

export default function Post() {
  return <div>HelloWorld</div>
}
```

加上这段代码后，Next.js 才会明白你的意图，并在打包时将其优化输出为静态文件：

- `.next/server/app/posts/1.html`

- `.next/server/app/posts/2.html`

- `.next/server/app/posts/3.html`

如果不配置 `generateStaticParams`：

- **构建阶段**：Next.js **不会**为这个动态路由预先打包生成任何 HTML 文件。

- **运行时（用户访问时）**：

  - 当用户首次访问 `/posts/1` 时，Next.js 会采用 **按需渲染（On-Demand SSR）**，即实时在服务器跑一遍 `PostPage` 拉取数据并生成 HTML。

  - 用户**第一次访问时会感知到明显的渲染延迟**（需要等待服务器拉取数据并渲染）。
