## 为什么需要NextJS

| 方案                         | 渲染模式  | SEO 能力                |
| ---------------------------- | --------- | ----------------------- |
| **纯 Vue**（Vue CLI / Vite） | CSR / SPA | ❌ 极差，空壳 HTML       |
| **纯 React**（CRA / Vite）   | CSR / SPA | ❌ 极差，空壳 HTML       |
| **Next.js**                  | SSG / SSR | ✅ 优秀，预渲染完整 HTML |
| **Nuxt.js**                  | SSG / SSR | ✅ 优秀，预渲染完整 HTML |

## CSR

客户端渲染

浏览器拿到几乎空的 HTML（只有一个 `<div id="root">` 和一个 `<script>`），下载并执行 JS 后才由 JS 生成整棵 DOM。缺点是首屏白屏时间长、SEO 差。

## SSR

服务端渲染

服务器把组件渲染成完整 HTML 字符串返回，浏览器立刻就能显示。首屏快、SEO 好。

## Hydration（水合）

- 脱水

服务端渲染出来的只是一段静态标记：没有事件监听、没有组件状态、没有交互逻辑。按钮看起来能点，点了没反应。这个阶段叫“脱水”状态。

```js
// server.js —— 运行在 Node
app.get('/', (req, res) => {
  const html = renderToString(<App />);
  res.send(`
    <body>
      <div id="root">${html}</div>
      <!-- 客户端 JS 在这里被"种"进页面 -->
      <script src="/assets/client.js"></script>
    </body>
  `);
});
```

- 水合

让 HTML 复活的过程，就是水合：干瘪的 HTML 加上客户端 JS 这瓶“水”，就活了。

```js
// client.js —— 打包产物，浏览器下载后执行
import { hydrateRoot } from 'react-dom/client';
import App from './App';

hydrateRoot(document.getElementById('root'), <App />);
```



## SSG

如果你现在做静态官网，用的是 **App Router**，那么**只要不碰 `cookies()`、`headers()` 这类动态 API，默认就是静态生成（SSG）**，无需额外配置。



## 使用NextJS构建静态官网

静态官网的**主体内容应该写在服务端组件（默认）中**，只在**需要浏览器交互**的地方使用客户端组件。

| 场景                                        | 用服务端组件                    | 用客户端组件            |
| ------------------------------------------- | ------------------------------- | ----------------------- |
| **页面主体内容**（文字、图片、布局）        | ✅ 默认即可，SEO 友好，JS 包更小 | ❌ 增加不必要的客户端 JS |
| **导航菜单**（纯链接跳转）                  | ✅ 服务端组件                    | ❌                       |
| **表单提交**（需要 onSubmit、useState）     | ❌ 无法绑定事件                  | ✅ `"use client"`        |
| **轮播图/动画**（需要 useEffect、DOM 操作） | ❌                               | ✅ `"use client"`        |
| **第三方库**（如图表、地图 SDK）            | ❌ 依赖浏览器 API                | ✅ `"use client"`        |

### 打包构建

Next.js 的静态生成（SSG）分为两个阶段：

**1. 构建时（Build Time）**

- 运行 `next build` 时，Next.js 会遍历所有页面

- 对每个页面执行一次渲染，生成完整的 HTML 文件

- 这些文件存放在 `.next/server/pages/`（或 App Router 的 `.next/server/app/`）目录下

**2. 运行时（Runtime）**

- 用户请求 `/about` 页面时，Next.js 服务器**直接读取并返回**已经生成好的 `about.html`

- 这个过程和 Nginx 返回静态文件一样，**不涉及 React 组件重新执行、不调用数据获取函数、不重新渲染**



对于静态官网：

- **2 个用户、2000 个用户请求同一个页面**：Next.js 都是**直接返回同一个预生成的 HTML 文件**，响应时间极快（毫秒级），服务器负载极低

- 每个用户浏览器收到 HTML 后，React 会进行**水合**让页面具备交互性，但这是客户端行为，和服务器端是否重新渲染无关
